### 2. Definições tomadas antes do propose
- **Pastas**: projetos de produção em `src/`, testes em `tests/`.
- **Forma de execução**: o usuário cria tudo manualmente no Visual Studio; o agente não gera código nesta change. O agente atua na mentoria e, depois, na validação contra os critérios de aceite.
- **Entrega do roteiro**: passo a passo em menus do Visual Studio 2022, não em linha de comando.
- **Pacotes NuGet**: o agente mentora a adição de cada pacote; a validação vem depois, e só então o arquivamento.

### 4. Estrutura especificada

```
GESTAO_FINANCEIRA/
├── GEF.sln
├── Directory.Build.props
├── stylecop.json
├── src/
│   ├── GEF.Domain/          Class Library      net8.0
│   ├── GEF.Application/     Class Library      net8.0
│   ├── GEF.Infrastructure/  Class Library      net8.0
│   └── GEF.UI/              WPF Application    net8.0-windows
└── tests/
    └── GEF.Tests/           xUnit Test Project net8.0
```

**Regras de dependência**: Domain não referencia nada; Application → Domain; Infrastructure → Domain + Application; UI → Application + Infrastructure; Tests → as três camadas internas, nunca a UI.

**Pacotes por projeto**: EF Core 8.0.x confinado à Infrastructure; Serilog e `Microsoft.Extensions.DependencyInjection` na UI; FluentAssertions 7.x nos testes; StyleCop.Analyzers para todos via `Directory.Build.props`. Domain e Application ficam sem pacote nenhum. AutoMapper, Swagger, SendGrid e Hangfire ficam fora por não terem uso nesta fase.

### 5. Questões abertas decididas pelo usuário
- **`stylecop.json` nesta change**, não depois. Desligadas SA1600/1601/1602 (documentação de todo membro), SA1101 (`this.` obrigatório), SA1309 (campo com `_`), SA1633 (cabeçalho de licença) e SA1200 (usings dentro do namespace).
- **`MainWindow` mantém o nome do template.** Ficou registrado o limite da regra de português: vale para código de negócio, não para artefatos da plataforma. Views e ViewModels novos seguem português.
- **`GEF.Tests` único**, com pastas internas `Domain/`, `Application/` e `Infrastructure/` espelhando as camadas.

Com isso, `design.md` ficou sem *Open Questions*.

### 6. Pontos técnicos que ficaram documentados
- O `.sln` na raiz é o único passo que o Visual Studio dificulta (ele força uma subpasta com o nome da solução) — daí o `dotnet new sln -n GEF`, com a alternativa 100% GUI registrada.
- Configuração do StyleCop precisa de **dois lugares**: `stylecop.json` para as regras que têm chave de configuração, `NoWarn` para SA1101 e SA1309, que não têm.
- `AdditionalFiles` usa `$(MSBuildThisFileDirectory)` porque os projetos estão um nível abaixo, em `src/` e `tests/`.
- Nunca colocar `TargetFramework` em `Directory.Build.props`: sobrescreveria o `net8.0-windows` do `GEF.UI` e quebraria o WPF.
- FluentAssertions 8 passou a ter licença comercial; a linha 7.x segue Apache 2.0.
- O `.gitignore` atual (VisualStudio.gitignore padrão) já cobre `bin/`, `obj/`, `.vs/` e os arquivos do LocalDB — nada a ajustar.
